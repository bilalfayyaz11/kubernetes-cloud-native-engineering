# Kubernetes Ingress Routing

## Overview

This implementation demonstrates advanced HTTP/S traffic management in Kubernetes using the NGINX Ingress Controller.

It routes multiple applications through a shared ingress layer using both path-based and host-based routing while terminating TLS at the edge.

## Architecture

~~text
                   External Client
                         |
                         v
              NGINX Ingress Controller
                         |
                TLS termination
                         |
          +--------------+--------------+
          |                             |
          v                             v
     myapps.local                 api.myapps.local
          |                             |
     +----+----+                        |
     |         |                        |
     v         v                        v
   /app1     /app2                     /
     |         |                        |
     v         v                        v
 app1-service app2-service        app2-service
     |         |                        |
     v         v                        v
   App 1      App 2                  App 2
~~

## Routing Rules

~~text
https://myapps.local/        -> app1-service
https://myapps.local/app1    -> app1-service
https://myapps.local/app2    -> app2-service
https://api.myapps.local/    -> app2-service
~~

HTTP requests are redirected to HTTPS.

## Components

- 2 nginx applications
- 2 replicas per application
- 2 ClusterIP Services
- NGINX Ingress Controller
- TLS Secret
- host-based routing
- path-based routing
- HTTPS termination
- readiness probes

## Requirements

A Kubernetes cluster with an NGINX Ingress Controller.

For Minikube:

~~bash
minikube addons enable ingress
~~

Verify:

~~bash
kubectl get pods -n ingress-nginx
kubectl get ingressclass
~~

## Deploy

Create the namespace:

~~bash
kubectl apply -f namespace.yaml
~~

Deploy both applications:

~~bash
kubectl apply -f app1.yaml
kubectl apply -f app2.yaml
~~

Generate the TLS certificate and Secret:

~~bash
./generate-tls.sh
~~

Apply the Ingress:

~~bash
kubectl apply -f ingress.yaml
~~

## Local DNS

Obtain the Kubernetes node address:

~~bash
kubectl get nodes -o wide
~~

For a local Minikube environment, add entries such as:

~~text
<MINIKUBE_IP> myapps.local
<MINIKUBE_IP> api.myapps.local
~~

to `/etc/hosts`.

## TLS Termination

TLS is terminated at the Ingress Controller.

Traffic flow:

~~text
Client
  |
 HTTPS
  |
  v
Ingress Controller
  |
 HTTP inside cluster
  |
  v
ClusterIP Service
  |
  v
Application Pod
~~

The included certificate generator creates a self-signed certificate containing SAN entries for:

~~text
myapps.local
api.myapps.local
~~

Self-signed certificates are suitable for local validation only.

~~bash

  -n web-apps
~~

Check application endpoints:

~~bash
kubectl get endpoints \
  -n web-apps
~~

Check controller status:

~~bash
kubectl get pods \
  -n ingress-nginx
~~

Inspect controller logs:

~~bash
INGRESS_POD=$(kubectl get pods \
  -n ingress-nginx \
  -l app.kubernetes.io/component=controller \
  -o jsonpath='{.items[0].metadata.name}')

kubectl logs \
  -n ingress-nginx \
  "$INGRESS_POD"
~~

## Security Notes

The TLS certificate generated by this implementation is self-signed and intended for local environments.

Production environments should use:

- trusted certificates
- automated certificate lifecycle management
- cert-manager or managed certificate services
- secure DNS
- appropriate ingress policies
- restricted controller annotations

## Production Improvements

For production environments:

- use cert-manager
- use trusted public/private CA certificates
- configure DNS automation
- use Gateway API where appropriate
- add rate limiting
- add authentication at the edge
- define NetworkPolicies
- add Web Application Firewall controls
- add observability and metrics
- configure ingress autoscaling
- define resource quotas
- configure high availability for the ingress controller
